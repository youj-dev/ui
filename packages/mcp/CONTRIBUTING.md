# Working on @youj/mcp

What it is: the MCP server for AI coding tools, as an npm package and as a remote Worker at mcp.youj.dev. What it does for users is in [README.md](README.md).

## House rules

What typically drifts here. The root [Principles](../../CONTRIBUTING.md#principles) apply too.

- The index (`data/*.json`) is generated from the workspace by `pnpm -F @youj/mcp generate`. It is never committed or edited. If you change docs, components, icons or blocks, it follows on its own.
- A tool returns Markdown sized for a model, has a title, description, input schema and `annotations`, and a test in `test/`.
- The published package has no dependencies; the build bundles them. Keep `node:` imports out of `src/server.ts`, `src/catalog.ts` and the tools, so the Worker runs.
- Surface snapshots (`test/surface.test.ts`) change only through `pnpm api:update`.
- Deploy the Worker with `cf:deploy`, never `wrangler deploy`, and only when asked.
- Mind the Worker size budget (`cf:build` fails over 8 MB, 2 MB gzipped).

## Layout

```
src/             the server: server.ts registers the tools, src/tools/ holds one file per tool group
scripts/         build-index.ts (the index), licenses.ts
worker/          the remote server (Streamable HTTP), with the index bundled in
data/            the generated index (data/*.json, and data/sources/ with one file per block file); not committed
```

## Adding a tool

Put the logic in a file under `src/tools/`, register it in `src/server.ts` with `server.registerTool` (a title, a description, an input schema and its `annotations`), and cover it in `test/`. The remote Worker serves the same tools, so a tool that reads the local project (like `get_project_info`) is registered only when `options.remote` is false.

## How it is built

- Everything returns Markdown sized for a model's context.
- `data/*.json` is the index, generated by `scripts/build-index.ts` from the workspace: the registry fragments, the docs' props extractor, every docs page (rendered by `apps/docs/lib/markdown.ts`, the renderer `/llms-full.txt` uses), the icons explorer's catalog and search, the blocks, the loaders and the UI tokens. The block files are not in it: they are one file each under `data/sources/` (their install paths), so a server reads only the ones a call needs. It isn't committed: `build`, `test` and `pack` regenerate it, so it always matches the sources. To refresh it by hand:

  ```bash
  pnpm -F @youj/mcp generate   # after changing docs, components, icons, blocks or examples
  pnpm -F @youj/mcp verify
  ```

- The build bundles the MCP SDK, zod and the theme code from `@youj/core` into one file (`dist/server.mjs`), so the published package has no dependencies.
- Try it locally: `pnpm -F @youj/mcp build`, then point an editor at `node <repo>/packages/mcp/dist/server.mjs`, or `npx @modelcontextprotocol/inspector node packages/mcp/dist/server.mjs`.
- Remote server: `worker/index.ts` serves the same tools (minus `get_project_info`) over Streamable HTTP at the root of `mcp.youj.dev` (a plain GET gets a note on how to connect), stateless, with `data/*.json` bundled in and `data/sources/` served as Workers static assets (the `ASSETS` binding, `runWorkerFirst`, so the Worker answers every request), fetched per call and cached per isolate. It needs no `nodejs_compat`: nothing in its import graph touches `node:` or `process` (the disk and the local app are behind `Catalog.host`, which only `src/data.ts` and `src/tools/project.ts` fill in; keep `node:` imports out of `src/server.ts`, `src/catalog.ts` and the tools). It lives here so it shares the source, index and tests. `pnpm -F @youj/mcp cf:build` bundles the Worker (Cloudflare's limit is 64 MB uncompressed on every plan; the block files stay out of the bundle as assets); `pnpm -F @youj/mcp cf:check` builds and dry-runs the deploy; `pnpm -F @youj/mcp cf:deploy` ships it with `cf` (never `wrangler deploy`).

## Commands

`pnpm -F @youj/mcp typecheck|test|generate|verify`, and `pnpm -F @youj/mcp cf:check|cf:deploy` for the Worker.
