# Working on @youj/react

What it is: accessible React components built on **shadcn/ui (Base UI variant, `base-nova` style)**, re-skinned to youj's art direction and animated **only** through `@youj/motion`. It's the sibling of `packages/motion` (read its [CONTRIBUTING.md](../motion/CONTRIBUTING.md) for the art direction) and builds on `@youj/core`. What it does for users is in [README.md](README.md).

## House rules

What typically drifts here. The root [Principles](../../CONTRIBUTING.md#principles) apply too.

- **What goes where:** a **component** is a thing a user clicks, types into or reads (`src/components/ui`). A **block** is a copy-in card, section, screen or frame that composes public components. Every item needs a `taxonomy.json` entry, and may use only items of its own level or lower.
- Components get their built-in text from core labels (`useComponentLabels`, in every locale). Blocks take a `copy?: Partial<XCopy>` prop and `locale`, and never write `en-US`. Blocks are usable as-is: data, copy, actions and theme are props, and they keep their size when state changes.
- **Shapes, colors and time come from tokens.** Components paint with roles (no `/N` tints, no `dark:` color forks, no raw colors or durations: `lint:tokens`). A control family reads its own shape token; nothing that renders a kit control sets its corner, height, edge or field fill (`lint:shapes`, or `// shape: <reason>`).
- Use `m.*` for motion, spread `useYoujScope()` on every Portal, and replace shadcn animate classes with Youj presets. Set `data-reduced-motion` and style with the `reduced:` variant.
- Add shadcn components only through `pnpm -F @youj/react ui:add <name>`, never `shadcn add` directly.
- Names follow the vocabulary (`vocabulary.test.mjs`): `size` is `sm | default | lg`, severity is `danger` not `destructive`, errors go through Field, `inView` not `trigger="view"`.
- `src/index.ts`, the entries and the registry are generated: run `pnpm -F @youj/react generate` after adding or renaming. A new export must be classified in `public-api.json`, and a public change needs `pnpm api:update`.
- Relative imports inside the package (never `@/`). Files stay small: `lint:structure` enforces the limits for blocks.

## Layout
```
src/components/ui/<name>.tsx   components, with <name>.stories.tsx, <name>.test.tsx and <name>.variants.ts beside them
src/blocks/<group>/<name>.tsx  blocks: cards, sections, screens and frames (copy-in)
src/hooks/, src/lib/utils.ts   shared hooks and helpers
src/styles/ui.css, shadcn.css  UI-only tokens and the opt-in shadcn compat sheet
src/index.ts and the entry files (chart.ts, form.ts, …)   generated, never edited
scripts/                       generators and checks; public-api.json, entries.json   the API allowlist and the entries
```

## Adding a thing
- **A component:** the "New-component checklist" and "Adding a shadcn component" below.
- **A block:** the "Blocks" section.
- Then run `pnpm -F @youj/react generate` and add its `taxonomy.json` entry.

## The layering rule
- **UI owns the things:** Button, Input, Dialog, Tabs, Table, and anything else a user clicks, types into or reads.
- **Core owns the contract, motion owns how things move:** tokens, the provider and `useYouj` are `@youj/core`; the motion primitives, transitions and effects are `@youj/motion`. **Icons are `@youj/icons`**, a dependency of this package; illustrations (`@youj/illustrations`) and miniatures (`@youj/miniatures`) are for blocks only, never a component (take a node slot instead).
- `@youj/react` depends on `@youj/core`, `@youj/motion` and `@youj/icons`. **Never the reverse.**
- A UI component never hard-codes timing. Every animation goes through `useYouj()` (`k.spring('snappy')`, `k.tween('fast','enter')`) or `var(--yj-duration-*)` with `ease-standard|enter|exit|emphasized`, so the Storybook Speed and Reduced-motion controls reach it.
- If a component needs a reusable motion behaviour (overlay presence, a sliding indicator, collapse, a morphing label), that behaviour belongs in `@youj/motion`. Import it from there.

## Tokens
- `packages/core/src/styles/youj.css` owns the Tailwind import and derives the **roles** (core's `ROLES`: `canvas`, `surface`, `overlay`, `well`, `field`, `key`, `control`, `chrome`, `chrome-float`, `inverse`, the lines, `fg`/`fg-muted`/`fg-subtle`, `hover`/`selected`/`band`, the inks with their `-text`/`-subtle`/`-line`, the chart). `src/styles/ui.css` is loaded after it and adds UI-only tokens such as radius, control heights, density and shadows. Components paint with roles only; the role table is the theming docs page (generated from `ROLES`).
- **Tone scopes:** a component that is chrome (sidebar, app header, toolbar, menubar, tab bar, island, capsule) writes `data-yj-tone="chrome"` on its root, every overlay content root `data-yj-tone="overlay"`, the tooltip `"inverse"`, and each sets `text-fg` itself. Roles re-derive inside, so a two-tone theme (`tone.chrome: 'dark'`) reaches the children with no selectors. `tests/storybook/tone.spec.ts` proves it.
- **No tints by opacity:** never `/N` on a role (`bg-fg/10`, `border-accent/30`); use `hover`, `selected`, `band`, `line-subtle` or `<ink>-subtle`/`-line`/`-text`. `lint:tokens` enforces it, along with no `dark:`/`light:` colour forks.
- **shadcn's names** (`background`, `primary`, `muted`, `popover`…) are not Youj's and Youj source never reads them; `src/styles/shadcn.css` is the opt-in compat sheet for apps that do. shadcn's hover surface `accent` is **`hover`** here; `scripts/shadcn-add.mjs` wraps `shadcn add`, rewrites its names to roles and lucide imports to Youj icons (failing on unmapped icons). Always add components through it.
- Use no raw colours, no stock Tailwind palette, and no raw durations.

## Components
- They live in `src/components/ui/<name>.tsx` in shadcn file style, with stories next to them (`<name>.stories.tsx`, titled `UI/<Group>/<Name>`) and tests (`<name>.test.tsx`).
- Imports: **relative paths** inside the package (the `scripts/shadcn-add.mjs` wrapper rewrites shadcn's `@/` imports to relative), `@youj/core` / `@youj/core/<path>` for the provider, tokens and labels, `@youj/motion` / `@youj/motion/<path>` for motion, `@youj/icons/components/youj/icons/<name>` for an icon, and declared deps. Never `@/` in package source, since it breaks when the package is consumed from another app.
- Base UI is `@base-ui/react` 1.8, pinned to `~1.8.0` because Field imports two of its internals (`internals/field-root-context`, `internals/labelable-provider`) that any minor may change. `field-base-ui.test.tsx` guards their shape; moving to a new minor means re-checking Field, then the pin. TanStack Table is **v9**. Check the installed APIs in node_modules, not memory.
- Accessibility is non-negotiable: correct roles, full keyboard support, visible `focus-visible` rings, and live-region announcements where state changes silently.
- Every story must work in both themes, with reduced motion, and at every Speed setting.
- A component's own classes are written with the `own:` variant (a layer below the style recipes), so a consumer's `className` beats both the component and the Bezel recipe. `lint:tokens` checks it; `packages/ui/scripts/codemods/own-variant.mjs` adds it (`ui:add` runs it on new components). Never reset the host app's Tailwind colors or spacing.

## Conventions
- **Style recipes are server-safe.** A component's `cva` recipe (`buttonVariants`, `badgeVariants`…) lives in `<name>.variants.ts` beside it, with no React in it and no `"use client"`, so a server component can call it. The component re-exports it, and `scripts/generate.mjs` exports it from the barrel through the recipe's own file (a name re-exported from a client module is a client reference). `packages/core/scripts/use-client.test.mjs` holds every `*.variants.ts` free of React.
- **Reduced motion in CSS:** components set `data-reduced-motion` from `useYouj()` and style with the `reduced:` variant, not `motion-reduce:`. That way the provider's "always"/"never" setting reaches CSS, not just the OS setting.
- **New tokens:** a new `@theme` text or spacing token must also be added to the `cn` lists in core's `src/lib/youj/cn.ts` (the one `cn`; `src/lib/utils.ts` only re-exports it for the components), or tailwind-merge silently drops classes.
- **Shared helpers live in `src/lib/utils.ts`,** which ships as `youj-ui-core` (the generator maps only that file, so a helper in another `lib/` file breaks `registry:check`): `initials`, `clamp`, `formatBytes`/`byteParts`, `toneColor`, `cssVars`, and cached `numberFormat`/`dateTimeFormat`/`relativeTimeFormat`/`listFormat`. Don't build an `Intl.*` formatter in render; use these. They stay server-safe (no React hooks: a server page imports this file); hooks live in `src/hooks/` (`useResizeMeasure` measures an element now and on every resize). Components import them; blocks keep a small local copy (a block never depends on a newer core than the one its user installed).
- **Focus:** use the `focus-ring` utility for discrete controls and `focus-field` for text fields.
- **Sizing:** heights use `h-control*`, and type sizes use `text-ui*`.
- **Token lint:** `pnpm -F @youj/react lint:tokens` also rejects shadcn leftovers: `transition-all`, stock `duration-*`/`animate-spin`, `bg-white`, `accent-foreground` and `@/` imports.

## Using motion in components (read [packages/motion/docs/ui-motion.md](../motion/docs/ui-motion.md) first)
- **Motion elements are `m.*`, never `motion.*`,** inside `<MotionFeatures>` (`features="max"` for layout/drag). See ui-motion.md; token lint enforces the import.
- **Every Base UI `Portal` gets `{...useYoujScope()}`.** Portals render outside the provider's wrapper, so without it overlays ignore Speed and forced reduced motion.
- **Replace shadcn's tw-animate classes** (`animate-in`, `fade-in-0`, `zoom-in-95`, `slide-in-from-*`, …) with youj presets (`yj-pop`, `yj-dialog`, `yj-sheet-*`, `yj-toast`, `yj-collapse`, …).
- **Use the motion transitions** instead of hand-rolled motion: SlidingIndicator (tabs, segmented, toggle groups), Collapse, ContentSwap, PresenceList (`@youj/motion`). Async buttons use AsyncButton (`onAction`, or `status` for work started elsewhere); plain Button only has `loading`.
- **Sound:** emit the fitting cue with `useSoundCue()` where the motion starts, behind `sound?: boolean` (default true); never import `@youj/sound`.
- **Native scroll regions** (`overflow-*-auto`) get `yj-scrollbar`, unless the bar is deliberately hidden.
- **Tables animated with PresenceList** use `border-separate` with borders on the cells, not `border-collapse`.

## Generated files and theming
- **After adding a component or hook,** or changing its imports, run `pnpm -F @youj/react generate`. It regenerates src/index.ts and the registry, and `verify` fails until they're current.
- **The public API is an allowlist:** `public-api.json` lists, per item, the names the entries re-export (`public`) and the ones they don't (`internal`: class strings, helpers shared with a sibling). A new export fails `generate` until classified; `node scripts/generate.mjs --write-api` records it (a `*Class` constant as internal), and the diff is the review. No `*Class` constant may be public (`scripts/check-surface.mjs`).
- **Attributes and variables:** Youj's own attributes are `data-yj-*`; the standard ones (`data-slot`, `data-state`, Base UI's) stay unprefixed (guides/styling-hooks). A new unprefixed `data-` name fails `scripts/check-surface.mjs` (older ones sit in `surface-baseline.json`, which only shrinks). Internal CSS variables are `--ui--*`; `api/youj-surface.md` snapshots the public ones.
- **Optional peers:** recharts, react-hook-form, date-fns, react-day-picker, embla-carousel-react and cmdk are optional peers. A component whose runtime imports reach one (directly or through another component, e.g. anything built on Command) leaves the main entry and ships from `@youj/react/<chart|form|date|carousel|command>`, or from an entry of its own when the group name would misfile it (`OWN_ENTRIES`: `/data-table`, `/workspace-switcher`); `generate` places it and writes `entries.json`, which the CLI, docs and MCP read. A new heavy dependency becomes an optional peer plus an entry in `OPTIONAL_ENTRIES` (scripts/generate.mjs), `exports` and `publishConfig.exports`.
- **Shapes come from the theme, in one place.** Each control family has one corner in ui.css: `rounded-button*` (buttons, toggles), `rounded-field*` (inputs, select triggers, pickers; `rounded-field-area` for a field that grows past one line), `rounded-choice*` and `rounded-choice-key` (a pill track and the key inside it, concentric), `rounded-chip` (badges, chips), `rounded-surface` (cards) and `rounded-overlay`/`-lg` (popups, dialogs); each follows the theme's `controls` unless the theme sets `--yj-shape-<family>`, and fields follow its `fields` style (outlined or soft). A component reads its own family's token; nothing that renders a kit control (a block, an example, another component) sets its corner, height, edge or field fill: use the control's props (`size`, `variant="ghost"` on a SelectTrigger, Badge `size`) or the family tokens. A genuine exception (a record button that is round in every theme, an editor bare inside a frame that is the field) carries `// shape: <reason>` in the tag or just above it; `lint:shapes` (in `verify`, docs too) fails without one. Heights use `h-control*`.
- **Dark styling:** prefer the ui.css token route over Tailwind's `dark:` variant. `dark:` matches any dark ancestor, so it mis-styles a light scope nested in a dark page.

## Levels (taxonomy.json)
Every component and block has a level and category in `taxonomy.json` at the repo root: component (simple or composite, its `complexity`), card, section, frame or screen. Cards, sections, screens and frames are the Blocks. A new item needs an entry, or `generate` fails; `pnpm check:taxonomy` (part of verify) checks the mapping. An item may use items of its own level or lower, never a higher one (`pnpm lint:ladder`). The docs document each level on its own pages (components, and the Blocks groups Cards, Sections and Screens); never mix levels in one list. Frames are the exception: their parts (sidebars, top bars, account, search, the shell) are chosen in Create and installed by its export, with no docs page, and the screens tagged `inApp` in `taxonomy.json` are what Create offers to add to a frame.

## Blocks
- `src/blocks/<group>/<name>.tsx` holds full-page, copy-paste compositions. They use ONLY public components, as an app developer would.
- **Export names:** a block's exported component is the PascalCase of its file name (`setup-wizard` exports `SetupWizard`), with no `Page` suffix (the level comes from `taxonomy.json`). A bare common noun that an app would already have (`Footer`, `Team`, `Security`, `Metrics`) takes its group as a prefix (`MarketingFooter`, `MarketingTeam`), as `MarketingNavbar` and the `Frame*` parts do. The group may also qualify the name where the file leaves it out (`SurveyForm`, `LogsTable`). `ErrorScreen` keeps its suffix because `Error` is a global.
- The generator turns each into a `registry:block` item named `<group>-<name>`, installed at `blocks/…`. Blocks are not exported from `src/index.ts`.
- Stories are titled `Blocks/<Group>/<Name>` and render at full viewport. Each declares what the block is in `parameters.showcase.kind`: `screen` (a whole screen), `section` (a full-bleed band of a page), `card` (a card or panel that sits inside a page), `overlay` (a drawer, popover or banner over a page; its story shows it open over `docs/placeholder-page`'s `PlaceholderPage`) or `fragment` (a piece of something larger: a sidebar, a top bar, a set of empty states). The generator fails without it and writes it to the item as `meta.kind`; the docs frame, capture and group each block by it.
- **A block is usable as-is.** If a developer has to edit its source to show their data, wire an action or change a string, it isn't done. Every block follows one API, with these exact names (the docs' block pages generate Usage and Props from it, `apps/docs/scripts/props.ts`):
  - **Data:** domain-noun props (`kpis`, `members`, `plans`, `events`) with block-prefixed item interfaces (`DashboardKpi`, `PricingPlan`) in its `data.ts`, re-exported from the entry with `XProps` and `XCopy`. Defaults are the demo's data, so stories and gallery pictures don't change.
  - **Strings:** `copy?: Partial<XCopy>`, `XCopy = typeof DEFAULT_COPY`: every user-facing string, aria-labels and toasts included; a string with a value in it is a function.
  - **Locale:** a block that formats takes `locale?: string` and formats in `useLocale(locale)` (`@youj/core`), so the provider's locale reaches it; a block whose copy carries `locale` resolves `useLocale(locale ?? copy.locale)` and types it `typeof DEFAULT_COPY & { locale: string }`. It never writes `'en-US'`: that's the provider's fallback, not the block's.
  - **Theme:** a block inherits the app's theme. `theme?: ThemeInput` is undefined by default and goes straight to `<ThemeScope theme={theme}>` (an undefined theme scopes nothing), so a block dropped into an app wears the app's preset. Its showcase look lives in its story (`args: { theme: graphite }`), never as a default in the block.
  - **Actions:** `on<Verb>` callbacks, `(payload) => Promise<unknown> | unknown`; the block awaits them (pending, then the rejection's message) where the demo had a fake wait.
  - **Unwired actions:** where the app passes no handler, the block keeps its demo behaviour through a local `demo('<Block>: on<Verb>', ms)` (beside its `wait`, in `data.ts` or the entry), never a bare `wait()` or a promise that resolves to success. In development it warns once per action, `<Block>: onX isn't wired; showing demo behaviour`; the check reads `process.env.NODE_ENV`, which bundlers replace, so production drops it. A server action the demo faked without a handler prop gets one.
  - **Demo data:** a block that simulates live data (an ops block's traffic, queue, pipeline or deliveries) does it only while its data prop is undefined, and then shows a dashed `Demo data` badge beside its title (`Badge variant="outline"`, `border-dashed border-foreground/25`, `data-slot="demo-marker"`) (`copy.demoData`, hidden with `demoMarker={false}`). Passed data turns the simulation off: the app re-renders the block with fresh data. Stories that keep the gallery picture clean pass `demoMarker: false`.
  - **State the app owns:** `value`/`defaultValue`/`onValueChange` (a named trio, `range`/`defaultRange`/`onRangeChange`, when there are several). Never `defaultX` without `onXChange`. Time comes in as `now`/`today`, never `Date.now()` in render.
  - **Lists and loads:** `loading`, `error` + `onRetry`, `empty` (default from `copy.empty…`).
  - **Composition:** `className` and `...rest` on the root; `classNames` for a large block's key parts; slots named `header`, `actions`, `footer`, `empty`, `aside`, `children`, `illustration`, `media`; `brand` for a product name and logo; `headingLevel`; links through `linkComponent?: ElementType` (default `'a'`) with `href` from the data (frame parts inherit it from `AppFrame`). Marketing CTAs are `cta`/`primaryCta`/`secondaryCta`: `{ label, href, onClick? }`.
  - **Density:** a block sets no `data-yj-density` of its own; it takes the page's (an app's root provider sets compact, the provider's default is roomy, and the docs and Storybook show each kind at its own), so the preview's Size control reaches it. An app sets one block apart with a `ThemeScope density` around it. `blocks/density.test.tsx` enforces this.
  - **A block keeps its size:** changing its state (filtering, switching a tab or view, opening an answer or row, posting, loading more) never makes the block grow or shrink. Variable content lives in a region of stable size that scrolls inside (`overflow-y-auto yj-scrollbar`, a fixed or `max-h-*` height sized for the demo, with a fade where it helps), empty and loading states take the same room as the content they replace, and a list that loads more scrolls rather than lengthening the page. An app can override the height (`className`/`classNames`); the default is still.
  - **A card is the card:** a `card` block's `embedded` defaults to true: the card alone, a `section` named by an `h2`, at its natural `max-w-*` (`fill` drops it), with no page around it. `embedded={false}` draws its own page (the centered `min-h-dvh` canvas and the `h1`). Its story renders the default; the docs and Storybook give it a stage (a `Standalone` story shows `embedded={false}`). An in-app screen (`inApp` in `taxonomy.json`, what Create adds to a frame) defaults `embedded` to true too: a page of the app's frame, in AppPage (its shared header: title, description, actions; the frame's gutter; `width="fill"` for a dashboard, table, board, canvas or a page of cards and lists, with fields capped at their own width, `"readable"`, centered, for a page that is one form), with no top bar, sidebar, breadcrumb or logo of its own. `embedded={false}` draws its own full page, and a `Standalone` story shows it. Any other screen or section keeps `embedded = false` as its default: there `embedded` means hosted inside another page.
  - A story `With your data` shows it fed with other data, and its test proves props drive content, `copy` rewrites text and callbacks fire. A block that is genuinely a demo says `Demo content — edit after adding.` in its header comment and story description.
- **Miniatures in a block** (the status family): the block takes the picture through `media` (default its miniature, `null` the plain page, or the app's own node), loads each miniature from a part file of its own through `lazy` (so `media={null}` and the states not shown load none; the stage keeps its size meanwhile), keeps it decorative (`interactive={false}` inside an `aria-hidden` stage, the meaning in text) and plays the page's state into it through its ref (`press`), `progress` and `done`. The part's static import makes the item depend on `@youj/miniatures`.
- **Links from data:** a block never puts a URL from props or user content into `href` as it is: pass it through `safeHref` (absolute http(s) or mailto) or, where relative links are fine, `safeLink` (`src/lib/safe-href.ts`); every `target="_blank"` link carries `rel="noreferrer"` (`lint:blocks` checks the `rel`).
- **Suppressions:** shipped code (components, blocks, lib) keeps both the `biome-ignore` and the matching `eslint-disable-next-line react-hooks/exhaustive-deps -- <reason>`, because consumers lint the copied files with eslint-config-next; `pnpm lint` fails on an `eslint-disable` without a reason.
- **`lint:blocks`** (part of `verify`, `scripts/check-blocks.mjs`) fails on a forced theme, a hard-coded `'en-US'` and a bare `wait()` in shipped block code. A genuine exception (a `formatToParts` that reads a time zone's clock, a wait that only paces an animation) carries `lint-blocks-allow: <why>` on its line or the line above. `blocks/host.test.tsx` renders every block inside a ThemeScope and fails on any theme of its own. `lint:blocks` also holds blocks to create-next-app's lint rule `react-hooks/set-state-in-effect` (no setState in an effect's body: set it while rendering, in an event, or in a callback the effect schedules).
- **Size:** a block installs as one file by default and stays under 400 lines. A bigger one keeps its entry at `src/blocks/<group>/<name>.tsx` (so its item name and install path hold) and moves its parts into a sibling folder `src/blocks/<group>/<name>/` (`<part>.tsx`, `data.ts`), each under 300. The generator ships that folder with the block. `lint:structure` enforces this.

## New-component checklist
Before a component ships, it answers each of these. `scripts/vocabulary.test.mjs` (part of `verify`) and `src/test/shadcn-traps.test.tsx` hold the ones that can be checked; the rest are review.
- **Size** comes from core's `Size` scale: `sm | default | lg`, with `xs` and `xl` only where the component needs another step (`Extract<Size, 'sm' | 'default'>`). Never `md`, `medium` or `large`. `size` is how big one control is; the provider's `density` is how much room a layout takes. If `shadcn` has the component, use its sizes.
- **Severity** is core's `Status` (`info | success | warning | danger`) or a tone built from it (`accent`, `neutral` and `chart-1…5` may sit beside it). It is `danger`, named after the colour role: never `destructive`, `error`, `critical` or `negative`. A boolean `destructive` flag on an action is fine (it says the action cannot be undone); a severity is not.
- **Errors** go through `Field` + `FieldError` + `aria-invalid`: the control reads the surrounding Field (`useFieldControl`), it does not draw its own message. An `error` prop is a message (`string`, or `ReactNode` where it is only shown); a flag is `invalid`, never `error: boolean`.
- **In view:** a component that waits for the viewport takes `inView?: InView` (`false` plays on mount, `true` or `{ once, amount, margin }` plays in view), read with `resolveInView`. No `trigger="view"`, `once`, `amount` or `startOnView` props. `trigger` is an event (the icons' and ScrambleText's), never "mount or view".
- **Busy and async:** `loading` is a controlled busy state on a Button. Work a button runs itself is `AsyncButton` (`onAction`, or `status`, never both).
- **Sound and motion:** a `sound?: boolean` escape hatch if it emits a cue, timing from tokens, reduced motion handled, `useYoujScope()` on portals.
- **Data attributes:** the states it exposes (`data-state`, `data-variant`, `data-size`, `data-status`…) use the values of its props, and are listed on its docs page.
- **shadcn compatibility:** if it replaces a shadcn component, a prop that shadcn has and that would compile but misbehave here is a type error that names the fix (see `OnSelectIsOnClick` in dropdown-menu.tsx) and a line in `shadcn-traps.test.tsx`.
- **Story, test, docs page** (with Accessibility), and a stability label no higher than its dependencies'.
- **A renamed prop** is renamed outright while Youj is pre-release (no alias). From 0.1.0 on, rename through the deprecation path in RELEASING.md.

## Adding a shadcn component
Never run `shadcn add` directly. Use the wrapper: `pnpm -F @youj/react ui:add hover-card`. It runs `shadcn add` in a throwaway copy of the package, then copies the new files into `src/` through a rewrite: `@/` imports become relative paths, shadcn's `cn` becomes the package's own `lib/utils`, and `accent` classes become `highlight`. It never runs a package manager and never edits `ui.css`; it prints any CSS the item wanted and any dependency it tried to install. Existing files are kept unless you pass `--overwrite`. Then finish by hand: replace tw-animate classes with a preset and spread `useYoujScope()` on portals, take durations from `useYouj()` or a `yj-duration-*` utility, set `data-reduced-motion` where CSS needs `reduced:`, write its story and tests, and run `lint:tokens` and `verify`.
