# @youj/cli

> Alpha (0.x): APIs can change between minor versions. See [Versioning](https://www.youj.dev/docs/versioning).

Sets Youj up in a React app with one command. It needs Node.js 22 or later.

```bash
npx @youj/cli init
```

It recognises Next.js (App and Pages Router), Vite, React Router v7 and Astro, your package manager (pnpm, npm, Yarn, Bun) and Tailwind CSS, and installs Tailwind v4 if it's missing. It asks for the mode (the `@youj/react` package, or the source copied in), a theme preset (Basalt by default), the component look (classic by default, or bezel), the motion personality and the default quality, then installs the packages (`@youj/react`, `@youj/core`, `@youj/motion`, `@youj/icons` and `motion`), adds the stylesheet after Tailwind and wraps the app in `YoujProvider`. Every change is shown as a diff; running it again changes nothing.

It loads the preset's fonts once, where the preset's stacks find them by name. Presets in the kit's own faces (Basalt, Graphite, Brutal and the six Wada presets: Inter and JetBrains Mono; Terminal: JetBrains Mono) get `@fontsource-variable/inter` and `@fontsource-variable/jetbrains-mono`, installed and imported where the app imports its stylesheet: their stacks ask for `'Inter Variable'` and `'JetBrains Mono Variable'`, the names @fontsource registers (next/font and Google register `Inter`, which the stacks never match). It also drops the rest of create-next-app's starter stylesheet: its `:root` colours, the `@theme inline` that pins the faces to Geist, and `body`'s background, colour and `font-family: Arial`, which would override the theme. Only an app with shadcn components of its own, or a stylesheet that still reads shadcn's variables, gets `@youj/react/shadcn.css`. `create` on the App Router moves a theme's faces to next/font (`lib/fonts.ts`, read through `lib/theme.ts`) and drops that import.

What would restyle Youj goes, after a diff and a question in a terminal (with `--yes`, the diff is in the summary): create-vite's starter stylesheets (`src/index.css`, `src/App.css`, recognised by their landmarks), and in a shadcn app its `@custom-variant dark (&:is(.dark *))` (Tailwind keeps the last `dark` variant, so Youj's `dark:` classes would match nothing), the `@theme inline` lines that map Youj's names to shadcn's variables (`--color-accent: var(--accent)` turns every `bg-accent` transparent once shadcn's `:root` goes) and shadcn's `:root` and `.dark` variable blocks (a variable of the app's own in them stays). On a hydrated `<html>` (Next.js App Router, React Router) it adds `suppressHydrationWarning`, which ThemeScript and next-themes need.

The colour scheme follows the visitor: init puts the early theme script in `<head>` (`<ThemeScript />` from `@youj/react` in a server-rendered layout, the same code inline in `index.html` or an Astro layout). It sets `data-theme` on `<html>` before the page paints, from the choice an uncontrolled `ThemeToggle` or `setThemeMode()` stored, or the system's until there is one. In an app that already has next-themes, init leaves the scheme to it and says so. On copied source a server-rendered layout has no ThemeScript, so init puts `data-theme="dark"` on `<html>` there instead.

| Command | What |
| --- | --- |
| `init [--yes] [--mode package\|registry] [--theme <preset>] [--look classic\|bezel] [--motion-personality precise\|calm\|lively] [--quality auto\|high\|low] [--dry-run]` | Set up the app. On Vite with the registry it sets the `@/` alias up where it's read: `paths` in `tsconfig.json` (the file shadcn reads) and `tsconfig.app.json` (Vite's split layout), and `resolve.alias` in the Vite config. The style goes on `<html>` (`data-yj-look`); classic, the default, needs nothing on `YoujProvider` (a root provider writes it), while bezel is `look="bezel"` there. On the registry bezel's stylesheet is copied in (`youj-look-bezel`, with the core) and imported right after ui.css; classic has none. The copy never lets shadcn prompt (`--yes --overwrite`, then the files that were there are settled as `add` settles them), so it can't stop halfway without a terminal: a file of the app's own where the core goes, a core file that didn't arrive or a failed shadcn run stops init with exit code 1 before the stylesheet or layout points at anything, and a run after that copies the core again |
| `create '<link>' [--mode package\|registry] [--overwrite] [--allow-low-contrast] [--dry-run]` | Set the app up from a [Create](https://www.youj.dev/create) link: Youj itself, the theme and its typefaces, the frame's blocks and screen, and an app shell. A theme that misses WCAG AA contrast (text 4.5:1, control boundaries 3:1) is refused unless you pass `--allow-low-contrast` |
| `add <items…> [--overwrite] [--path <dir>] [--dry-run\|--diff\|--view]` | Copies each item's source into the app. It never prompts, with or without `--yes`: a file that's already there and the same as Youj's (bar formatting and the `'use client'` line) is left alone and counted in one line, one you changed is kept and listed at the end, and `--overwrite` replaces it. In an app on the package, a component isn't copied: `add chart` installs `recharts`, an optional peer of `@youj/react`, and says to import from `@youj/react/chart`. A block is copied on its own (`copy-in.ts`): the CLI fetches it and its registry dependencies, leaves the ones a package ships (read from the installed packages' export maps, `exports.ts`), points the block's imports of them at the package entries, copies only what no package ships (other blocks, a block's parts), installs the Youj packages and optional peers its imports need, and sets up the `@/` alias if it's missing. No shadcn, no `components.json`, no CSS. On the registry it drives shadcn's installer (flags pass through), then puts back any import that installer pointed at a same-named file; it checks the `@/` alias first and stops, naming the file to fix, instead of letting shadcn write into a literal `./@/` folder. A file of the app's own that a Youj item imports and that can't stand in for Youj's (a shadcn component, built on Radix or missing a name the item imports; `collisions.ts`) isn't kept quietly: in a terminal `add` asks to replace it, and otherwise it stops with exit code 1 and the `--overwrite` command. `lib/utils.ts` is merged, `--overwrite` or not: shadcn's stock one is replaced by Youj's (its `cn` does the same and knows Youj's tokens), and one with helpers of the app's own moves to `lib/utils.local.ts`, which Youj's re-exports. An app the core was copied into but that never imported its stylesheet is told to run `init --mode registry`. `add loader-<id>` installs `@youj/loaders` and the item is imported from `@youj/loaders/<id>`. `add sound` installs `@youj/sound` (or copies its source in an app on the registry) and gives the app's `YoujProvider` `sound={beacon}` (on the Next.js App Router through a client `app/providers.tsx`, since a pack can't cross from a server layout) |
| `doctor [--strict]` | Check versions, the stylesheet and its order (and fail on shadcn's leftovers in it, and on an `@import` of a file that isn't there), the provider (followed through the files the root imports, such as `app/providers.tsx`) and duplicate copies (of `motion` and `@youj/core`, which holds the provider's state and is a peer the app should list itself, and on the package, copied Youj files that duplicate what the packages ship; a shadcn app's own components are named as its own), and wherever source is copied the `@/` alias (tsconfig, Vite config, a stray `./@` folder, copied `@/` imports that resolve to nothing) and copied Youj code importing a file that can't stand in for Youj's; prints fixes. `--strict` fails on what's to look at too, and runs the app's own TypeScript (`tsc --noEmit`, or `tsc -b` for Vite's split tsconfig) |
| `mcp [--yes] [--client claude\|cursor\|vscode\|windsurf\|codex\|gemini\|zed\|jetbrains\|all] [--print] [--dry-run]` | Add the Youj MCP server (`@youj/mcp`) to the editor's config: `.mcp.json`, `.cursor/mcp.json`, `.vscode/mcp.json`, Windsurf's `~/.codeium/windsurf/mcp_config.json`, Codex's `.codex/config.toml`, `.gemini/settings.json`, `.zed/settings.json`, or (printed to paste, JetBrains AI Assistant keeps them in a dialog) JetBrains, merged with what's there and pinned to the app's Youj version. `init` offers it as its last step |

`create` takes the whole link, in quotes (it has `?` and `&` in it), or just its query string. In an app without Youj it runs `init --yes` first, with the theme's preset and motion. It writes the theme to `lib/theme.ts` and points `YoujProvider` (and `themeProps` on `<html>`) at it, adds the frame's blocks and its screen through `add`, and writes the shell that composes them to `components/app-shell.tsx`, all under `src/` when the app has one. A theme in web fonts gets them loaded: on the App Router, `lib/fonts.ts` sets them up with next/font and their variables go on `<html>` in the root layout; anywhere else, the Google Fonts stylesheet is imported at the top of the global stylesheet. On the App Router the screen becomes a route too, `app/(app)/<screen>/page.tsx`, whose group layout wraps it in `<AppShell>`, so it opens in the frame; elsewhere, wrap your pages in `<AppShell>` and render the screen's block. A file that's already there stays unless you pass `--overwrite`, and the same link twice changes nothing. A link without `look` is classic, the default: an app that names its own look keeps it. A bezel link (`look=bezel`) puts `data-yj-look="bezel"` on `<html>` and `look="bezel"` on the provider, with its stylesheet copied in and imported after ui.css on the registry; a provider that names another style is left as it is, with a note. A link that names a size (`layout=roomy`, `scale=110`) sets `density` and `scaling` on the provider to it, replacing the ones there; one without leaves an existing provider's size alone (`init` leaves the provider at its own standard size, roomy at 100%, with no size props).

After adding items, `create` puts back any `@/` import shadcn pointed at the wrong same-named file (adding several items at once, it resolves an import by its last segment, so a block's `…/data` can land on another block's data file, and `@/components/ui/data-table` on its `data-table.tsx`).

All take `--cwd <dir>`. `YOUJ_NPM_REGISTRY` points the app's `@youj` scope at another npm registry.

**Which registry.** The docs site serves every release's items at `/r/v<version>/<name>.json`, and the latest at `/r/<name>.json` (the alias the shadcn directory lists). The CLI reads its own version's, `https://www.youj.dev/r/v<its version>/{name}.json`, so what it copies matches the packages it installs and doesn't change with each deploy of the site; `init --mode registry` writes that URL into `components.json`. `--latest` on `init`, `create` and `add` (or `YOUJ_REGISTRY_LATEST=1`) reads the alias instead. An item newer than the CLI is a 404 that says so: run `npx @youj/cli@latest`, or pass `--latest`. `YOUJ_REGISTRY_URL` overrides both (a template with `{name}`, or a base URL).
