### Accessibility

Every screen is a `main` with one heading (an `h1` by default; set `headingLevel` where the page around it needs another). The miniatures are decoration: each is a still, unfocusable picture (`interactive={false}`) inside an `aria-hidden` stage, so the headline, the text and the live regions carry the meaning, and each follows reduced motion, showing its states at once. The status code is read as plain text: a small line over the headline beside a miniature, set large on the plain page.

Status screen's loading state sets `aria-busy` on the page and announces its headline through a `status` region; its progress bar is a labelled `progressbar`, with no value while the wait is unknown, and the line that offers a reload is a `status` as well. The 503's automatic retries run through its Try now button, so each attempt and its outcome are announced (Retrying…, Still down, Back online); the countdown to the next one is plain text, never read out every second. After a 403 request, the line saying what happens next is a `status`. The 404's search is a `search` landmark with a labelled field. Request tracking announces a found request politely, lists the steps as an ordered list with the current one marked `aria-current="step"` and each step's state spelled out for screen readers, and shows lookup errors under the field (`aria-describedby`).

Actions that wait on a server (Try again, Try now, Request access, Notify me, Track) are Buttons with `onAction` or a `status`: they show progress and the result in text as well as motion. Links and buttons are real `a` and `button` elements with the kit's focus ring. Everything animated stands still under reduced motion.
