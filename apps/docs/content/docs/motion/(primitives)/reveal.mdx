Use it for content that should arrive rather than appear: a hero's headline, a section as it scrolls in, a panel that opens. One Reveal moves one element. For a group, use [Stagger](/docs/motion/stagger), and for a headline that assembles word by word, [TextSplit](/docs/motion/text-split). Don't reveal what people came to read or act on, like form fields, table rows or navigation. It should be there when they look.

## Usage

Wrap anything. By default it rises into place the first time 30% of it is on screen.

```tsx
import { Reveal } from '@youj/motion'

export function Feature() {
  return (
    <Reveal>
      <FeatureCard />
    </Reveal>
  )
}
```

Use `inView={false}` for content that should arrive as soon as it renders, and `as` to reveal a heading or list item without an extra wrapper.

```tsx
<Reveal as="h2" inView={false} className="text-4xl font-semibold">
  Motion that lands where you meant it.
</Reveal>
```

### Variants

Eight arrivals share one timing model. `rise`, `fade` and `scale` take the `slow` duration. The four `wipe-*` variants and `blur-in` travel further, so they take `deliberate`. Everything that travels decelerates hard into place on the `enter` curve. `fade` doesn't travel, so it uses `standard`.

### Choreography

`delay` is a count of stagger steps, not milliseconds. `delay={2}` waits two `delayStep` steps. The whole sequence stays on the token grid, so it scales with the Speed control and never drifts out of rhythm.

```tsx
<Reveal inView={false} delay={0} delayStep="loose">Eyebrow</Reveal>
<Reveal inView={false} delay={1} delayStep="loose">Headline</Reveal>
<Reveal inView={false} delay={2} delayStep="loose">Body</Reveal>
```

For lists, reach for [Stagger](/docs/motion/stagger): it hands each child its cue, and a `Reveal` inside it takes its timing and delay from the parent.

</Example>

<Example id="exits" label="Exits">

### Exits

Inside `AnimatePresence`, a Reveal leaves with the `fast` duration on the `exit` curve. Exits are shorter than arrivals, because nobody waits for something to leave. Toggle quickly: a re-entry mid-exit retargets from wherever the element is, without a jump.

It animates only `opacity`, `transform`, `filter` and `clip-path`, so a reveal never triggers layout.

#### Reduced motion

A Reveal renders in its final state from the first frame: no fade, no travel and no wait. Inside `AnimatePresence`, it's removed at once. Nothing is hidden behind a scroll position, so the page reads the same either way.

<ReferenceRow title="Accessibility" summary="ARIA">

### Accessibility

- The content is in the document from the first render, so assistive technology reads it whether or not it has animated in.
- Reveal adds no roles. Put semantics on the element itself, with `as`.
- Scroll reveals are one-shot by default (`inView={{ once: true }}`). Content that disappears as it scrolls away makes a page feel unstable, so opt out only with a reason.

</ReferenceRow>
