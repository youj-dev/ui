<Story id="demo" label="Demo">

<ComponentPreview name="color-picker/demo" height={280} />

A brand color field with a live preview of a button and a link in the chosen color.

- **The area** sets saturation across and brightness up and down. Click or drag anywhere in it. The thumb follows the pointer exactly, and glides to a new place when the color changes from a swatch or a field.
- **The hue** is a [Slider](/docs/components/slider) on a spectrum track, from 0 to 359 degrees.
- **The eyedropper** samples any pixel on screen, in browsers that have one. Elsewhere the button isn't shown.
- **The fields** take hex and OKLCH. They commit on Enter or when they lose focus. Something they can't read is marked invalid, and put back on blur.
- **Swatches** default to the theme presets' accents, and the selected one is ringed.

</Story>

<Story id="oklch-and-your-own-swatches" label="OKLCH and your own swatches">

<ComponentPreview name="color-picker/oklch" height={200} />

A picker in OKLCH with five label swatches of your own, and the value it holds shown under it.

`format="oklch"` makes `onValueChange` report OKLCH strings, which suit a theme built on perceptual lightness. `swatches` replaces the presets with your own `{ value, label }` pairs, and `swatches={[]}` removes the row.

</Story>

## Installation & usage

<InstallTabs name="color-picker" noImport />

Use it when people choose any color: a brand accent, a label, a chart series, a theme. The trigger shows the swatch and hex in the width of a text field, and the popover holds every way in: drag in the area, slide the hue, type a hex or OKLCH value, pick a swatch, or sample the screen with the browser's eyedropper. When the choice is one of a few named colors, a [Toggle Group](/docs/components/toggle-group) or a [Radio Group](/docs/components/radio-group) of swatches is quicker.

```tsx
import { useState } from 'react'
import { ColorPicker, Field, FieldLabel } from '@youj/react'

export function BrandColor() {
  const [color, setColor] = useState('#3554fc')
  return (
    <Field>
      <FieldLabel>Brand color</FieldLabel>
      <ColorPicker value={color} onValueChange={setColor} aria-label="Brand color" />
    </Field>
  )
}
```

`value` takes a hex or OKLCH string. The color is held as hue, saturation and brightness inside, so dragging to gray or black and back keeps the hue you had.

</Example>

<ReferenceRow title="Touch" summary="On a touch device the picker opens in a bottom sheet">

### Touch

On a touch device the picker opens in a bottom sheet. The area is taller and its thumb larger, swatches are 44px targets, and the fields use 16px text so the page doesn't zoom. Dragging in the area or along the hue slider changes the color and never pulls the sheet down; pull from the handle or the space around the controls to close it, or tap outside it.

`presentation` chooses: `auto` (the default) is a popover under a mouse or trackpad and a sheet on touch, `sheet` always uses the sheet, and `popover` keeps the popover on touch too.

</ReferenceRow>

<ReferenceRow title="Accessibility" summary="Keyboard, ARIA, focus">

### Accessibility

- The trigger reads its label and the current value, such as "Brand color, #3554fc".
- The area is one focusable `slider` thumb whose value text names both axes. ArrowLeft and ArrowRight step saturation, ArrowUp and ArrowDown step brightness, and Shift steps by 10.
- The hue slider is named "Hue" and reads its value in degrees.
- Swatches are toggle buttons in a group named "Swatches", each named by its `label` and marked `aria-pressed` when selected.
- Escape closes the popover and returns focus to the trigger, as every [Popover](/docs/components/popover) does.

</ReferenceRow>
