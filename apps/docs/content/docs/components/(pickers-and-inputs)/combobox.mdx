A reviewer field that searches a directory through a simulated 650 ms request and shows a loading row while it waits.

Pass `onSearchChange` and the built-in filtering turns off: fetch the matches yourself and pass them as `options`. While `loading` is true the list shows a loading row, which is announced, and the empty message waits until the results arrive.

## Installation & usage

<InstallTabs name="combobox" noImport />

Requires `cmdk`, an [optional dependency](/docs/installation#optional-dependencies). Import it from `@youj/react/command`.

Use Combobox to choose one value from a list that needs search, such as a directory of people. Use [Multi-select](/docs/components/multi-select) for several values, or [Tag Input](/docs/components/tag-input) for free-form entries. For short lists, use [Select](/docs/components/select) or [Radio Group](/docs/components/radio-group).

```tsx
import { useState } from 'react'
import { Field, FieldLabel } from '@youj/react'
import { Combobox } from '@youj/react/command'

const regions = [
  { value: 'iad1', label: 'Washington, D.C.', group: 'Americas' },
  { value: 'fra1', label: 'Frankfurt', group: 'Europe' },
  { value: 'hnd1', label: 'Tokyo', group: 'Asia Pacific' },
]

export function RegionField() {
  const [region, setRegion] = useState<string | null>('fra1')
  return (
    <Field>
      <FieldLabel>Region</FieldLabel>
      <Combobox options={regions} value={region} onValueChange={setRegion} placeholder="Choose a region" />
    </Field>
  )
}
```

The trigger is a field-styled button with `role="combobox"`, named by the `FieldLabel` around it. It opens a [Popover](/docs/components/popover) holding a [Command](/docs/components/command), so the search, the gliding active row and the list's height all behave like the command menu. Each option has a `value` and a `label`, and can add a `description` (searched too), an `icon`, a `group` heading, extra `keywords` and `disabled`. `onValueChange` hands you the value and the option.

Typing a letter on the closed trigger opens it with that letter already searched. With `clearable`, a clear button sits in the trigger, and Delete or Backspace clears the value from the keyboard.

<ReferenceRow title="Long lists" summary="Past 100 options only the best matches are mounted">

### Long lists

Every mounted row costs a registration, a score and a re-render on each keystroke, so past 100 options the Combobox mounts only the 100 best matches, in order of match, and ends them with a note ("Showing 100 of 2,000. Keep typing to narrow the results."). Searching reaches every option. With 2,000 options a keystroke takes about 35 ms where it took about 120 ms, and clearing the search about 0.07 s where it took 0.2 s (Chromium on a laptop, development build; 4x CPU throttling shows the same ratios).

- **Up to 100 options:** everything is mounted and cmdk filters, as before.
- **100 to about 5,000 options:** pass them all. The filter runs on every keystroke over all options, which stays under a few milliseconds per thousand. Define the `options` array outside render, or memoise it, so unchanged rows aren't re-rendered.
- **More than that, or options that live on a server:** use `onSearchChange` and pass the matches. Your results are cut to 100 rows too, so return the best 100 or fewer.

</ReferenceRow>

<ReferenceRow title="Touch" summary="On a touch device the list opens as a bottom sheet with a grab…">

### Touch

On a touch device the list opens as a bottom sheet with a grab handle, the search field at the top and 48px rows. It opens with the list in view and the on-screen keyboard down; tap the field to search. While the keyboard is up, the sheet sits on top of it and is only as tall as the space that's left, so the field stays visible, and it keeps its height as results narrow so the field doesn't jump. A tap on a row picks it and closes the sheet. Pull the sheet down, tap outside it or press Escape to close it without picking, and focus returns to the trigger.

`presentation` chooses: `auto` (the default) is a popover under a mouse or trackpad and a sheet on touch, `sheet` always uses the sheet, and `popover` keeps the popover on touch too.

</ReferenceRow>

<ReferenceRow title="Accessibility" summary="Keyboard, ARIA, focus">

### Accessibility

- The trigger has `role="combobox"` and is named by its `FieldLabel`, or by `aria-label` when it has no label. The description and error of its Field describe it, and `aria-invalid` and `aria-required` follow the Field.
- ArrowDown, ArrowUp, Enter or Space opens the list. Typing a character opens it with that character searched. In the list, arrows move, Enter picks and returns focus to the trigger, and Escape closes.
- The chosen row carries `aria-checked` and a drawn check. Groups are labeled by their heading.
- In a long list each row carries `aria-setsize` (all matches) and `aria-posinset`, so assistive tech announces "3 of 2000" rather than "3 of 100"; the note under the rows is announced when the list opens and as the search changes.
- Clearing, from the button or with Delete, is announced ("Selection cleared") and focus stays on the trigger. The clear button is named "Clear selection".
- The loading row is announced politely, and the empty message isn't shown until loading ends, so "No results" is never read out for results that are still coming.
- With `name`, a hidden input submits the value with a native form.

</ReferenceRow>
