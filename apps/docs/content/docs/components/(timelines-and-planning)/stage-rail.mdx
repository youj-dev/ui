## Installation & usage

<InstallTabs name="stage-rail" noImport />

Use a stage rail for work that moves through ordered stages: build, test and deploy in CI, the steps of a migration, the phases of a rollout. Each stage is a key in a recessed track holding its name, its duration (ticking in mono while it runs), a run of cells that fill as it progresses and its state: queued, running, passed, failed or skipped. The cells of every stage share one line, so the run reads as a single bar: ink where work is done, the accent where it's under way, the danger tone where it broke, hatched where a stage was skipped. Picking a stage raises its key, so the rail can drive whatever sits below it, such as that stage's log. For steps a person works through, use a [Stepper](/docs/components/stepper).

```tsx
import { useState } from 'react'
import { StageRail } from '@youj/react'

export function Pipeline() {
  const [stage, setStage] = useState('test')
  const testStartedAt = Date.now() - 20_000
  return (
    <StageRail
      stages={[
        { id: 'build', name: 'Build', status: 'passed', duration: 72_000 },
        { id: 'test', name: 'Test', status: 'running', startedAt: testStartedAt, estimate: 64_000 },
        { id: 'deploy', name: 'Deploy', status: 'queued' },
      ]}
      value={stage}
      onValueChange={setStage}
    />
  )
}
```

Times are in milliseconds. A running stage ticks from its `startedAt` and fills toward its `estimate` (what it usually takes), stopping short of full until it passes; pass `progress` (0–1) instead when you know it. A finished stage shows its `duration`, and a failed one fills to its `progress`, where it broke. Without `value`, the rail picks the running stage, else the first that failed, else the last to have run.

The rail is one toggle group with a stage always picked. Pass the id of the panel it drives as `controls`, and it sets `aria-controls` on every stage:

```tsx
<StageRail stages={stages} value={picked} onValueChange={setPicked} controls="stage-log" />
<div id="stage-log" role="log" aria-label={`${name} log`}>…</div>
```

Parts: `stage-rail`, `stage-rail-stage` (with `data-status`), `stage-rail-header`, `stage-rail-dot`, `stage-rail-label`, `stage-rail-track`, `stage-rail-cell` (with `data-state` `on` or `off`), `stage-rail-footer`, `stage-rail-status`, `stage-rail-value` and `stage-rail-indicator`. Units in the duration carry `data-part="unit"`. The names take the theme's label voice; in [Bezel](/docs/looks) the track is a recessed well, the picked stage a lit key and the figures mono.

<ReferenceRow title="Accessibility" summary="Keyboard, ARIA, announcements">

### Accessibility

- It's a toggle group named by `label` (default "Pipeline stages"): one tab stop, arrow keys move between stages (mirrored in RTL), Home and End jump, and Enter or Space picks. The picked stage has `aria-pressed="true"`; pressing it again keeps it picked.
- Each stage is named with its state and duration, as shown and then in words: "Test, Running, 42s, 42 seconds". The cells are hidden from assistive tech.
- A stage that changes state is announced politely: "Test, Passed".
- The state is always a word as well as a color and a dot shape.

</ReferenceRow>
