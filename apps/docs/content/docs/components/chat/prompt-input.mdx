<Story id="demo" label="Demo">

<ComponentPreview name="prompt-input/demo" height={300} />

A composer with a model select and a Search toggle, where send turns into stop while a pretend reply streams.

`status` is `idle`, `submitted` or `streaming`. Anything but `idle` turns send into stop, a real path morph from the arrow to a square, and Escape in the field stops too. Send stays focusable while it can't act, so keyboard focus is never dropped mid-reply.

`toolbar` puts your controls at the start of the bottom bar: a model select, tool toggles, dictation. The demo has a model [Select](/docs/components/select) and a [Toggle](/docs/components/toggle). Size them `sm` to sit on the bar.

</Story>

<Story id="attachments" label="Attachments">

<ComponentPreview name="prompt-input/attachments" height={280} />

A composer that attaches files by paperclip, paste or drop, shown as chips above the text.

Pass `onAttach` and a paperclip appears, and pasting or dropping files attaches them too. `accept` filters all three, as in `<input accept>`. Attachments sit above the text as chips, a thumbnail for images and name and size for files, each with its own remove button. `usePromptAttachments()` manages picked files for you: `add`, `remove` and `clear`, with object-URL previews revoked when they're removed or the component unmounts.

An attachment with `status: 'uploading'` blocks sending until it's ready, and one with `status: 'error'` says so.

</Story>

<Story id="limits" label="Limits">

<ComponentPreview name="prompt-input/limit" height={240} />

A 220-character limit with a long draft in the field, so the counter shows.

`maxLength` shows a counter near the limit and blocks sending past it. The counter appears from 80% of the limit, turns to a warning at 95% and to danger past it. Replace it with `counter`, for example `<PromptInputCounter value={tokens} max={8000} unit="tokens" />` to count tokens instead.

</Story>

## Installation & usage

<InstallTabs name="chat" imports="PromptInput" noImport />

Use it below a [Chat Message List](/docs/components/chat/message-list) for anything someone writes to an assistant. It handles the keyboard rules people expect from a chat composer, attachments by picker, paste and drop, and the switch from send to stop while a reply runs. For a plain multi-line field in a form, use a [Textarea](/docs/components/textarea).

```tsx
import { PromptInput } from '@youj/react'

<PromptInput status={status} onStop={stop} onSubmit={({ text, attachments }) => send(text, attachments)} />
```

`onSubmit` gets the trimmed text and the attachments. Uncontrolled, the field clears itself after sending. Control it with `value` and `onValueChange` to fill it from elsewhere, like a [suggestion](/docs/components/chat/suggestions), and `textareaRef` to focus it.

Enter sends and Shift+Enter breaks the line, and neither cuts an IME composition short. On touch keyboards Enter is a line break and the button sends. The field grows with the message up to 40% of the viewport, then scrolls.

<ReferenceRow title="Accessibility" summary="ARIA, focus, announcements">

### Accessibility

- The field is named by `label` (default "Message"). With `maxLength`, it's described by the counter and set `aria-invalid` past the limit.
- The counter is announced only in the last stretch (under 10% left) and when over, not on every keystroke.
- Send is named "Send message", and "Stop generating" while busy, with a tooltip. It stays focusable while it can't act.
- The paperclip is named "Attach files". Attachments are a list named "Attachments", and each remove button is named after its file. Removing one moves focus to its neighbor, never to the page.
- `disabled` grays the whole frame and blocks typing, attaching and sending.

</ReferenceRow>
