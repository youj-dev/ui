## Installation & usage

<InstallTabs name="chat" imports="ChatToolCall" noImport />

Use one for each function, search or API call an assistant makes, inside its [Chat Message](/docs/components/chat/message) before the answer. People see that the answer rests on real data, and can open the call to check exactly what went in and came out. For the model thinking without a tool, use [Thinking](/docs/components/chat/thinking).

```tsx
import { ChatToolCall } from '@youj/react'

<ChatToolCall
  name="get_deployments"
  args={{ project: 'orion', limit: 3 }}
  status={call.status}
  result={call.result}
  error={call.error}
  duration={call.ms}
/>
```

At rest it's one line: a status mark, the tool's name, a short read of its arguments and a badge. When the result arrives, a two-line preview unfolds under it. Opening the card shows the arguments and the full result, with JSON highlighted. `result` takes text or anything JSON can show, and `duration` (in ms) joins the badge once it's done. `open`, `defaultOpen` and `onOpenChange` control the card.

</Example>

<ReferenceRow title="Accessibility" summary="Keyboard, announcements">

### Accessibility

- The header is the card's disclosure button, named by the tool and its status ("get_deployments: Done · 1.5s").
- Each status change is announced once: through the conversation's live regions inside a [Chat Message List](/docs/components/chat/message-list), or its own status region on its own. Errors are assertive. A call that mounts already settled, as history, isn't announced.
- Long arguments and results scroll inside a named region, which becomes a tab stop once it overflows.

</ReferenceRow>
