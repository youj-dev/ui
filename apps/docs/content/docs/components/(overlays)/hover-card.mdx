## Installation & usage

<InstallTabs name="hover-card" noImport />

Use a hover card to let people peek at a link's destination without leaving the page: mentions, references, commit hashes. It's a visual shortcut for sighted pointer, touch and keyboard users, and the link stays the real interface, so everything in the card must also be at its destination. Keep controls out of the card. For content people open on purpose, including on touch, use a [Popover](/docs/components/popover). For a one-line label, use a [Tooltip](/docs/components/tooltip).

```tsx
import { HoverCard, HoverCardContent, HoverCardTrigger } from '@youj/react'

export function Mention() {
  return (
    <HoverCard>
      <HoverCardTrigger href="/people/priya">@priya</HoverCardTrigger>
      <HoverCardContent>
        <PersonSummary handle="priya" />
      </HoverCardContent>
    </HoverCard>
  )
}
```

`HoverCardTrigger` renders an `<a>`, so it stays a plain link: it navigates on click and reads as a link to assistive technology. Style it like the links around it.

## Reference

<ReferenceRow title="Props" summary="HoverCardTrigger passes through to Base UI's preview card trigger">

### Props

#### HoverCardContent

<PropsTable name="HoverCardContent" />

`HoverCardTrigger` passes through to Base UI's preview card trigger. Here it defaults `delay` to 500 and `closeDelay` to 250, and takes `href` and the other link attributes. `HoverCard` takes the root props (`open`, `defaultOpen`, `onOpenChange`).

</ReferenceRow>

<ReferenceRow title="Touch" summary="Touch has no hover, so on a touch device a tap on the link opens its…">

### Touch

Touch has no hover, so on a touch device a tap on the link opens its card instead of following the link. A second tap on the link follows it and closes the card, and a tap anywhere else closes the card without leaving the page. Base UI's preview card doesn't respond to touch on its own; `HoverCardTrigger` adds this. On a phone the card is still a preview: a screen reader user never sees it, so keep everything in it at the destination too.

</ReferenceRow>

#### Reduced motion

The card appears in place when the delay ends and closes at once. The delays are kept, because they separate a glance from a pass-by rather than animate anything.

<ReferenceRow title="Accessibility" summary="Keyboard, focus, announcements">

### Accessibility

- The trigger is an ordinary link, and it's the only accessible interface. The card isn't announced, and its content isn't in the tab order.
- Keyboard focus on the link opens the card, so keyboard users get the same preview. `Escape` closes it and leaves focus on the link.
- On touch, the first tap on the link shows the card and the second follows the link. The card's content isn't navigable by touch, keyboard or screen reader, which is why it must repeat what the destination says.

| Key | Action |
| --- | --- |
| `Tab` | Focusing the link opens its card. |
| `Enter` | Follows the link. |
| `Escape` | Closes the card and keeps focus on the link. |

</ReferenceRow>
