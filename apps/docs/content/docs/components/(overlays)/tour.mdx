A first-run tour of a small dashboard: the sidebar, search, the figures and Export, one at a time.

Each step dims the page and cuts a rounded hole over its target, with a card beside it: the step's title and text, the count ("2 of 4") and dots, Back, Next (Done on the last step) and Skip. Between steps the hole glides to the next target. The arrow keys go Back and Next, and Escape skips.

## Installation & usage

<InstallTabs name="tour" noImport />

Use a Tour to show someone around a screen they haven't used before, or a few new things on one they have. Keep it short: three to five steps, each about one thing they can see. For one new control a [Popover](/docs/components/popover) or a TourBeacon with a one-step tour is enough.

```tsx
import { useState } from 'react'
import { Button, Tour, type TourStep } from '@youj/react'

const steps: TourStep[] = [
  { target: '#search', title: 'Find any order', body: 'Search by number, customer or amount.' },
  { target: '#filters', title: 'Narrow the list', body: 'Filter by status, channel or date.' },
  { target: '#export', title: 'Take it with you', body: 'Export what you see as CSV.', placement: 'top' },
]

export function OrdersTour() {
  const [open, setOpen] = useState(false)
  return (
    <>
      <Button onClick={() => setOpen(true)}>Take the tour</Button>
      <Tour steps={steps} open={open} onOpenChange={setOpen} onComplete={markSeen} onSkip={markSeen} />
    </>
  )
}
```

A step's `target` is a CSS selector (the first match on the page) or a ref. A step whose target isn't on the page, or is hidden, is skipped in the direction you were going. `placement` puts the card on a side of the target (`bottom` by default; `top`, `inline-start` or `inline-end`), and it flips when there's no room. `action` adds your own content under the text, such as a link or a button that does the thing.

`open` and `step` can each be controlled (`onOpenChange`, `onStepChange`), or left to the tour with `defaultOpen` and `defaultStep`; an uncontrolled tour starts again from `defaultStep` each time it opens. `onComplete` runs when Done is pressed, `onSkip` with the step index when Skip or Escape ends it early.

To keep the tour inside part of the page, as these previews do, pass that element as `container` and give it `contain: paint` (or a `transform`), so the scrim covers it rather than the window.

#### Data attributes

<ReferenceRow title="Accessibility" summary="Focus, keyboard, ARIA, live region">

### Accessibility

- The card is a dialog named by the step's title and described by its text, followed by a hint on the keys. Focus moves into it (to Next) when the tour opens and stays in it while the tour runs.
- ← and → go Back and Next (swapped in right-to-left), Tab moves between the buttons, and Escape skips the tour when it's `dismissible`.
- Each new step is announced politely: "Step 2 of 4: Find any order".
- The spotlighted element is described by the step's text (`aria-describedby`) while it's shown, and its own description is put back afterwards.
- With `allowInteraction`, clicks reach the spotlighted element and focus isn't held in the card, so the element can be used from the keyboard too.
- The count and the dots say the same thing; the dots are hidden from assistive technology.
- `TourBeacon` is a button named "Start the tour" by default; pass `label` to say what it's about.

</ReferenceRow>
