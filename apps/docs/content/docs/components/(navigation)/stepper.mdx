<Story id="detour" label="Detour">

<ComponentPreview name="stepper/detour" height={260} />

A horizontal stepper with a detour drawn over the steps it bypasses.

`detour` draws a rerouted stretch on a horizontal stepper: a dotted arc in the accent leaves the step at `from`, passes over the steps it bypasses and lands on the step at `to`, with its `label` and `detail` riding the top. Bypassed steps carry `data-bypassed`. It's measured from the discs, so it follows resizes and RTL; a vertical stepper ignores it.

<Story id="flagged" label="Flagged">

<ComponentPreview name="stepper/flagged" height={200} />

A launch plan as dated milestones, with the submission deadline flagged.

`flagged` calls a step out without failing it: until it's done, its disc wears a flag and its description takes the danger ink, and the disc carries `data-yj-flagged`. The flag is decorative, so put the reason in the `description` ("Oct 30, deadline"), which is read with the title. Use `invalid` instead when the step has actually gone wrong.

## Installation & usage

<InstallTabs name="stepper" noImport />

Use a stepper to show progress through a fixed sequence people move through in order: checkout, onboarding, a setup flow. It shows state, it doesn't hold the steps' content. For a flow that shows one step at a time with Back and Continue built in, use a [Wizard](/docs/components/wizard), which draws its own stepper. For a flow that spans pages, with steps as links, use [Stepper Nav](/docs/components/stepper-nav). For progress that has no named steps, use a [Progress](/docs/components/progress) bar.

```tsx
import { Stepper, type StepperStep } from '@youj/react'

const steps: StepperStep[] = [
  { id: 'cart', title: 'Cart' },
  { id: 'shipping', title: 'Shipping' },
  { id: 'payment', title: 'Payment' },
  { id: 'review', title: 'Review' },
]

export function CheckoutProgress({ current }: { current: number }) {
  return <Stepper steps={steps} current={current} aria-label="Checkout" />
}
```

`current` is the index of the step in progress. Steps before it are complete, and `current={steps.length}` marks every step done. The current step's disc is the solid one, in the accent; done steps step back to a tint with their check, and upcoming ones are outlined. Pass `onStepClick` and done steps, and the current one, become buttons that go back to them. Upcoming steps stay inert, so the stepper can't skip ahead of the flow's own validation.

The fill is a transform on a Motion value, so going back mid-fill drains from where the fill is instead of restarting.

#### Reduced motion

Connectors fill and drain instantly, discs change color at once, the check and warning marks appear without drawing and a detour is drawn in place. The state reads exactly the same.

<ReferenceRow title="Accessibility" summary="ARIA, focus, announcements">

### Accessibility

- The stepper is an ordered list named "Progress" by default. Name it after the flow with `aria-label`.
- The current step has `aria-current="step"`, and every step's state is written out after its title for screen readers: "Payment, has an error".
- With `onStepClick`, the done steps and the current one are real buttons, and with `stepHref` they're links. Upcoming steps aren't focusable.
- The discs, connectors and marks are decorative (`aria-hidden`); the text carries the state.
- A detour's label is read after the step it leaves, with where it rejoins ("Detour, rejoins at step 4", `stepDetour` in the labels).
