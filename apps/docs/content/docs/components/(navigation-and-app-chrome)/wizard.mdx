A checkout wizard where the Payment step blocks Continue until a card number is entered.

`validate` runs when someone leaves a step forwards. Return `true` to move on, `false` to stay (the step's own field errors explain why), or a message, which appears under the step and is announced. It can be async: Continue shows a spinner while it runs. A failed step is marked in the stepper until it passes.

## Installation & usage

<InstallTabs name="wizard" noImport />

Use a wizard when a task is long enough to split but each part depends on the one before: creating a workspace, a checkout, importing data. It draws a [Stepper](/docs/components/stepper), shows one step's content, and handles Back, Continue, Skip and Finish. When every field fits on one screen, a single [Form](/docs/components/form) is quicker to fill in. When people need to compare the steps, don't hide them: lay them out as sections of one page.

```tsx
import { Wizard, WizardStep } from '@youj/react'

export function CreateProject() {
  return (
    <Wizard onComplete={() => createProject(values)} finishLabel="Create project">
      <WizardStep id="name" title="Name" validate={() => values.name.length > 0}>
        <NameFields />
      </WizardStep>
      <WizardStep id="repo" title="Repository" optional>
        <RepoPicker />
      </WizardStep>
      <WizardStep id="review" title="Review">
        <Summary />
      </WizardStep>
    </Wizard>
  )
}
```

Each `WizardStep` is a step: its `title` goes in the stepper and heads the content, and its children show while it's current. The wizard keeps the step index itself, or pass `step` and `onStepChange` to control it. On the last step, Finish runs `onComplete` through the [Button](/docs/components/button)'s `onAction`, so it shows a spinner and then a drawn check with `finishSuccessLabel`.

The drift follows the reading direction, so under RTL forwards comes in from the left. The outgoing step is popped out of the layout while it leaves, so rapid Back and Continue presses retarget the height without a jump.

#### Reduced motion

Steps replace each other in place with no drift or fade, and the panel height changes at once. Focus, announcements and validation are unchanged.

<ReferenceRow title="Accessibility" summary="Keyboard, ARIA, focus">

### Accessibility

- "Step 2 of 4" above the content is a polite live region that also speaks the step's title, so each move is announced.
- After Back or Continue, focus moves to the new step's heading, so a screen reader starts reading from the top of the step and a keyboard user tabs on into its fields.
- A validation message has `role="alert"`, and the failed step is spoken as "has an error" in the stepper.
- Done steps in the stepper are buttons that go back to them. Later steps can only be reached by Continue, so validation can't be skipped.
- Continue sets `aria-busy` while an async validation runs, and ignores presses until it settles.

</ReferenceRow>
