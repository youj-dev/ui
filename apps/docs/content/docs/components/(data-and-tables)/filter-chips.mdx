An Issues field holding the chips `label:bug` and `priority:in(p1,p2)`, with a hint to type `assignee:me` and a space.

Chips are keyed by their field (the text before the colon), so when a control changes a filter, its chip rewrites itself in place instead of leaving and coming back. Derive `value` from your filters, and parse the tokens back in `onValueChange`: the [Filter panel](/docs/blocks/forms-and-inputs) block's order search does both.

## Installation & usage

<InstallTabs name="filter-chips" noImport />

Use filter chips where filters also read as text: a log search, an order list, an issue tracker. Each filter is a chip like `priority:in(p1,p2)`, people who think in queries can type them, and the chips can mirror controls elsewhere on the page. For free-form values that aren't a query (topics, email domains), use a [Tag Input](/docs/components/tag-input).

```tsx
import { Field, FieldLabel, FilterChips } from '@youj/react'

export function IssueSearch() {
  const [query, setQuery] = useState(['priority:in(p1,p2)'])
  return (
    <Field>
      <FieldLabel>Issues</FieldLabel>
      <FilterChips
        value={query}
        onValueChange={setQuery}
        validate={(token) => (/^[a-z]+:\S/.test(token) ? undefined : 'Write a filter as field:value.')}
      />
    </Field>
  )
}
```

A token ends at a space, never inside brackets or quotes, so `priority:in(p1, p2)` stays whole. A finished `field:value` becomes a chip as you type the space after it, and Enter adds whatever is typed. A pasted query adds each of its tokens. Click a chip, or focus it and press Enter, and its text returns to the field to edit.

`validate` gets the new token and the current list, and returns a reason to refuse it. A refused token stays in the field: the frame shakes, the border turns destructive, and the reason grows in under it and is read out. A duplicate isn't added; the chip that already holds it flashes.

### Accessibility

- The field is named by its `FieldLabel`, `aria-label` or `aria-labelledby`, and the chips are a list named "Active filters". A refused token sets `aria-invalid` and is described by its reason, a `role="alert"` message.
- In the field, Backspace when it's empty, or the left arrow at its start, reaches the last chip. On a chip, the arrows move between chips, Home and End jump to the ends, Enter or F2 edits it, Backspace or Delete removes it and focus lands on its neighbor, and Escape returns to the field. Each chip describes these keys.
- Each chip's remove button is named after its filter. Additions, removals and duplicates are announced politely.
- With `name`, each token is submitted with a native form under that name.

</ReferenceRow>
