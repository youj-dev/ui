A file row's own delete: press it and the button splits into a cross and a tick, right where the person was looking.

Pressed, the trigger's box morphs into two icon buttons, a cross to cancel and a tick to confirm, and focus moves to the tick. The question (`prompt`) is the pair's accessible name and is announced. Confirming runs `onConfirm` as an [Async Button](/docs/components/button#async-button) does: a spinner, then a check or a cross; `pendingLabel`, `successLabel` and `errorLabel` are announced. Once the outcome has shown, the pair folds back into the trigger.

## Installation & usage

<InstallTabs name="inline-confirm" noImport />

Use an Inline Confirm for a small action that is easy to trigger by mistake, such as deleting a row, revoking a key or leaving a team, where a dialog would interrupt more than it helps. For a costlier action, use a [Slide to Confirm](/docs/components/slide-to-confirm) or `hold` on an [Async Button](/docs/components/button#hold); for one that needs explaining, use an [Alert Dialog](/docs/components/alert-dialog).

```tsx
'use client'

import { InlineConfirm } from '@youj/react'

export function DeleteFile({ file }: { file: File }) {
  return (
    <InlineConfirm destructive variant="ghost" pendingLabel="Deleting…" successLabel="Deleted" onConfirm={() => deleteFile(file.id)}>
      Delete
    </InlineConfirm>
  )
}
```

`onConfirm` is awaited: resolve for success, reject or throw for an error. A second press while it runs is ignored, and while it runs the question can't be dismissed. An open question that isn't answered folds back after `timeout` (5 seconds, paused while the pointer is on it); pass `timeout={false}` to wait for an answer.

</Example>

### Props

<PropsTable name="InlineConfirm" />

#### Data attributes

The root carries `data-state` (`closed` or `open`) and `data-size` (`sm`, `default` or `lg`). The confirm button is an Async Button with its own `data-state` (`idle`, `pending`, `success` or `error`) and `data-variant` (`danger` when `destructive`, else `default`). The parts are named `inline-confirm-box`, `inline-confirm-trigger`, `inline-confirm-cancel` and `inline-confirm-action` in `data-slot`.

<ReferenceRow title="Accessibility" summary="Focus, Escape, announcements">

### Accessibility

- The trigger is a button. Pressing it (click, Enter or Space) opens the question and moves focus to the confirm button.
- The open row is a `group` named by the question, which is also announced politely as it opens.
- Escape and Cancel fold it back and return focus to the trigger; Escape is handled here and doesn't reach a dialog or menu around it. Focus leaving the row folds it back too, and focus stays where it went.
- While `onConfirm` runs the confirm button is busy, Cancel is disabled and Escape does nothing. Pending and success are announced politely, an error assertively.
- When the row folds back on its own (the timeout, or after the outcome) with focus inside it, focus lands on the trigger rather than the page.
- With sound on, opening plays `open` and folding back plays `close`; the confirm sounds as an Async Button does. `sound={false}` keeps it silent.

</ReferenceRow>
