Errors from children, from an `errors` list, or from the control's own validation, easing open and closed.

FieldError shows what you pass it. Give it children for one message, or `errors` for several, in react-hook-form's `{ message }` shape: duplicates collapse, and several messages become a list. With neither, it shows the control's own validation message whenever Base UI marks the field invalid, from native constraints such as `required` or from a `validate` function, checked when `validationMode` says.

A message grows the layout open. Its panel eases from zero height while the text fades in, so the fields below move down with it instead of jumping. When the error clears, the panel closes over the last message. An error that's already there when the Field first renders simply appears, as the taken handle in the preview does.

## Installation & usage

<InstallTabs name="field" noImport />

Wrap form controls in Field to connect their labels, descriptions and errors for assistive technology. Group controls that answer one question with FieldSet and FieldLegend. A search or toolbar input already named by `aria-label` does not need a Field.

```tsx
import { Field, FieldDescription, FieldError, FieldLabel, Input } from '@youj/react'

export function WorkspaceName({ error }: { error?: string }) {
  return (
    <Field required invalid={!!error}>
      <FieldLabel>Workspace name</FieldLabel>
      <Input name="workspace" />
      <FieldError>{error}</FieldError>
      <FieldDescription>Shown in the sidebar and in invite emails.</FieldDescription>
    </Field>
  )
}
```

Field is Base UI's Field, so the wiring is correct by construction. FieldLabel names the control, FieldDescription and a visible FieldError describe it, and `invalid` and `disabled` reach it. `required` is Youj's addition: set it once on the Field and the label shows the mark while the control becomes required. Every Youj control works inside a Field: Input, Textarea, Input Group, Checkbox, Radio Group, Switch, Slider and Select.

## Reference

<ReferenceRow title="Structure" summary="Field, FieldLabel, FieldSet… (10 parts)">

### Structure

| Part | Renders | Use it for |
| --- | --- | --- |
| `Field` | `div` | One control with its label, description and error. |
| `FieldLabel` | `label` | The control's name. Wrapping a whole Field makes a choice card. |
| `FieldDescription` | `p` | Help text, added to the control's description. |
| `FieldError` | `div` | Errors, shown in a panel that grows in and collapses out. |
| `FieldContent` | `div` | The label-and-description column beside a horizontal control. |
| `FieldTitle` | `div` | A label-styled heading that doesn't label anything, for choice cards. |
| `FieldSet` | `fieldset` | A group of controls that answer one question. |
| `FieldLegend` | `div` | The group's name, linked to its fieldset. `variant="label"` sets it at label size. |
| `FieldGroup` | `div` | Stacks fields and sets. It's the container that `responsive` measures. |
| `FieldSeparator` | `div` | A hairline between groups, with optional text in the middle. |

Outside a Field, the label, description and error parts render as plain elements with the same look, so you can compose them freely.

</ReferenceRow>

<ReferenceRow title="Label" summary="a label outside a Field">

### Label

Outside a Field, use Label: a plain `<label>` with the same type, linked to its control by `htmlFor`. `required` shows the same decorative mark. It ships as its own registry item, `label`, which Field installs for you.

```tsx
import { Checkbox, Label } from '@youj/react'

<div className="flex items-center gap-2">
  <Checkbox id="terms" />
  <Label htmlFor="terms">Accept the terms</Label>
</div>
```

</ReferenceRow>

<ReferenceRow title="Custom control" summary="useFieldControl, useFieldRequired">

### Custom control

A control Base UI doesn't know, such as a popover trigger or a row of segments, joins the surrounding Field with `useFieldControl`. It returns `id` (what the FieldLabel's `htmlFor` points at), `labelId` (for `aria-labelledby` on roles a native label can't name), `describedBy` (the Field's description and error), and the Field's `invalid`, `disabled` and `required`. Outside a Field it returns a stable `id` and nothing else. Pass `{ labelable: false }` for a group whose first input already claims the label. `useFieldRequired` reads only the Field's `required`.

```tsx
import { useFieldControl } from '@youj/react'

function ColorSwatch({ value }: { value: string }) {
  const { id, describedBy, invalid, disabled } = useFieldControl()
  return (
    <button id={id} type="button" aria-describedby={describedBy} aria-invalid={invalid || undefined} disabled={disabled}>
      {value}
    </button>
  )
}
```

</ReferenceRow>

<ReferenceRow title="Accessibility" summary="ARIA, focus, announcements">

### Accessibility

- FieldLabel names the control: with `htmlFor` for inputs, and with `aria-labelledby` for composite controls such as Checkbox and Switch.
- FieldDescription and a shown FieldError are added to the control's `aria-describedby`, and `invalid` sets `aria-invalid` on it.
- FieldError is `role="alert"`, so an error announces itself when it appears. On submit, move focus to the first invalid control, as the first preview does.
- The required asterisk is `aria-hidden`. The control's own `required` is what assistive technology announces.
- FieldSet and FieldLegend make a named `group`, so a screen reader reads "Scopes, group" before the first checkbox.

</ReferenceRow>
