Addons on each edge of the control.

An addon sits on an edge set by `align`: `inline-start` (the default) or `inline-end` beside the control, or `block-start` or `block-end` above or below it. The edges are logical, so they swap sides under right-to-left text. Put icons straight in, and wrap text in InputGroupText.

## Installation & usage

<InstallTabs name="input-group" noImport />

Use an input group when something belongs inside the field's border: a search icon, a `https://` prefix, a unit, a copy button, a shortcut hint. If the extra piece is its own action next to the field, like a Send button after an email address, put a [Button](/docs/components/button) beside a plain [Input](/docs/components/input) instead.

```tsx
import { InputGroup, InputGroupAddon, InputGroupInput, Kbd, KbdGroup } from '@youj/react'
import { SearchIcon } from '@youj/icons'

export function Search() {
  return (
    <InputGroup>
      <InputGroupAddon>
        <SearchIcon />
      </InputGroupAddon>
      <InputGroupInput aria-label="Search" placeholder="Search projects…" />
      <InputGroupAddon align="inline-end">
        <KbdGroup>
          <Kbd>⌘</Kbd>
          <Kbd>K</Kbd>
        </KbdGroup>
      </InputGroupAddon>
    </InputGroup>
  )
}
```

The group is the frame. The InputGroupInput or InputGroupTextarea inside it is bare, and the frame takes its hover, focus halo, invalid and disabled treatment. Clicking an addon's empty space focuses the control, as it would on a native field. Buttons inside keep their own clicks and their own focus ring.

#### Reduced motion

The frame's border and halo change color as usual, since nothing moves. Buttons in the group lose their press scale, and async buttons swap states instantly.

<ReferenceRow title="Accessibility" summary="Keyboard, ARIA">

### Accessibility

- The frame is a `group`. The control inside is the labeled element: put the InputGroup inside a [Field](/docs/components/field) and the FieldLabel names the control, or give the control an `aria-label`.
- Icon-only buttons inside need an `aria-label`, like any icon-only button.
- A reveal button, like the password eye above, keeps one name and reports its state with `aria-pressed`.
- Keyboard hints such as <kbd>⌘</kbd> <kbd>K</kbd> are visual. If the shortcut matters, say it in the control's description too.
- Addons are `select-none` text. Anything in them that people need to read, like a unit, belongs in the label or description as well.

</ReferenceRow>
